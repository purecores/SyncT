# SyncT — Windows 11 个人双机专属实时文件夹同步工具 (Portable Release)

**SyncT** 是一款面向 **Windows 11** 平台构建的**纯原生单文件便携版 (Portable)** 实时文件夹同步桌面应用，底层基于 [MyGo](https://mygo.run/zh) 原生 UI 框架（无 CGO、无 WebView、直接编译为原生 Win32/Direct3D 11 硬件加速界面）与 **Cloudflare Tunnel (`cloudflared`)** 构建。

---

## 专属定制规格（本机服务端 <-> 工作电脑客户端）

1. **直接复用本机已运行的系统 Cloudflared (`sync.example.com` -> `https://localhost:18920`)**
   - **复用系统隧道 (`TunnelSystem`)**：通过纯 Go Win32 `CreateToolhelp32Snapshot` 实时检测本机系统已在后台运行的 `cloudflared.exe` 服务/进程（无需提权、无需再次填写 Token、绝不重复启动第二个 `cloudflared` 进程，停止同步时也不会干扰系统正在运行的 `cloudflared` 服务）。
   - **公网域名**：可通过环境变量 `SYNCT_PUBLIC_URL` 或设置页配置公网域名（例如 `https://sync.example.com`）。
   - **本地监听端点**：服务端默认监听 **`https://localhost:18920`**（同时绑定 `127.0.0.1:18920` 与 `[::1]:18920` 回环接口）。
   - **双协议自适应 + 自签名 TLS 证书**：内建自动生成 `localhost` / `sync.example.com` 的 ECDSA P-256 自签名 TLS 证书（保存在 `./data/localhost-cert.pem`），通过首字节嗅探在同一端口 `18920` 同时兼容 `https://localhost:18920` 与 `http://localhost:18920`。

2. **工作电脑 User 权限克制设计 (`asInvoker`)**
   - **内嵌 `asInvoker` Windows 权限清单 (`RT_MANIFEST`)**：PE 资源段中显式声明 `<requestedExecutionLevel level="asInvoker" uiAccess="false"/>`，在仅具普通 `User` 权限的工作电脑上运行**绝不弹出 UAC 管理员提权窗口**。
   - **工作电脑端零监听端口 & 零子进程**：工作电脑处于客户端模式（`RoleClient`），仅通过标准出站 HTTPS (`443`) 访问 `https://sync.example.com`，不监听任何本地端口（绝不触发 Windows 防火墙管理员弹窗），也不需要启动或附带 `cloudflared.exe`。
   - **100% 便携目录隔离**：所有配置文件 (`config.json`)、状态索引 (`state.json`)、窗口尺寸状态 (`window-state.json`)、缓存与日志均通过 `mygo.App.SetPath` 强制重定向至程序同级的 `./data/` 目录，**零注册表写入、零 `%AppData%` 写入、零系统目录访问**。

3. **多文件夹同步与跨机目录映射 (`LocalPath` ↔ `RemotePath`)**
   - **同时同步多个独立目录**：支持在主目录之外添加任意数量的受控同步文件夹，按目录标签与逻辑映射 ID (`default`, `projects`, `docs` 等) 独立开启/关闭与检索。
   - **跨电脑异构目录映射**：支持指定本机某个文件夹同步到另一台电脑的不同目标文件夹路径（对端连接握手时自动识别映射 ID 并创建/绑定对应的目标文件夹）。
   - **左下角实时吞吐面板**：侧边栏左下角与底部状态栏常驻展示实时上传/下载速率 (`↑` / `↓`)、文件与文件夹数量、总容量以及尚未同步的文件数。

4. **专属应用图标 (`internal/ui/app_icon.png`)**
   - 已将 `internal/ui/app_icon.png` 转换为多尺寸高清图标（`16px ~ 256px`）编译进 `rsrc_windows_amd64.syso`（EXE 文件图标、任务栏图标、窗口图标），同时内嵌至软件顶栏与 Windows 11 系统托盘图标。

## v1.2.0 界面与同步行为

- **主界面重做**：概览页只保留一块实时吞吐读数与 30 秒速率轨迹、四项关键指标（受控文件 / 未同步 / 映射目录 / 累计流量），以及同步文件夹与连接状态两张卡片。原先堆在概览里的隧道表单、密钥、端口、分享码和多文件夹编辑器全部收进「设置」页，按「文件夹与方向」「工作模式与连接」「文件规则」「运行与后台」「多文件夹与跨机映射」分组折叠。顶栏只留开始/停止、扫描与「更多」菜单。
- **速率真实**：速率不再按「单个文件传输耗时」折算（小文件会显示成数 GB/s 的虚高值），而是统计实际流过的字节在 2 秒滑动窗口内的速率；传输中持续更新，空闲约 3 秒后归零。
- **界面刷新**：引擎运行期间每 250ms 请求一帧，状态栏与概览的速率、未同步数量随手更新，不再等下一次文件传完。
- **未同步文件页**：侧边栏新增「未同步」，列出待同步、上传/下载中、冲突与失败的文件，可直接定位到资源管理器；状态栏同时显示未同步数量。主机端直接提供文件下载，因此主机本地文件视为已同步；可向对端上传的客户端会把新文件标为「待同步」，确认写入远端后转为「已同步」。
- **空文件夹同步**：清单新增目录列表，主机与节点都会创建对端存在的空文件夹（含多级嵌套）；新建空文件夹还会通过 SSE / `POST /api/dirs` 实时推送。
- **后台提示开关**：状态栏右下角新增「后台提示」开关，设置页「运行与后台」中也有同一开关，控制关闭主窗口隐藏到托盘时是否弹出一条系统通知（默认关闭）。
- **传输效率**：小文件使用 64 个并发传输槽位，大文件使用 4 个槽位并同时进行；HTTP 连接复用（`MaxIdleConnsPerHost 64`）并关闭传输层压缩；扫描时并行计算新/变更文件的 SHA-256，扫描结果直接用于上传，不重复读盘。

## 502 Bad Gateway 排查与自愈

工作电脑报「远端返回状态码 502」表示 **Cloudflare 边缘已连上隧道，但 cloudflared 无法从主机端取得响应**。SyncT 现在会在主机端自动区分并处理两类原因：

1. **主机端 SyncT 未运行或本地端口未监听**：客户端错误信息会直接提示「主机端 SyncT 可能未运行，或 Cloudflared 无法连接本地源站」；主机端每 15 秒自检本地源站（`http://127.0.0.1:18920`），监听意外失效时自动重建。固定端口不再静默改用随机端口——端口被占用会明确报错，因为随机端口必然导致公网 502。
2. **cloudflared 拒绝本地自签名证书**（`x509: certificate signed by unknown authority`）：本地证书只对回环服务有效，Cloudflare 托管隧道的源站若配置为 `https://localhost:18920` 且未开启 `No TLS Verify`，cloudflared 会拒绝自签名证书。主机端会读取本地 TLS 握手错误并在日志/概览中提示，工具栏出现 **「修复 502 (信任本地证书)」** 按钮：点击后以管理员权限把 `./data/localhost-cert.pem` 安装到「受信任的根证书颁发机构」并重启 `cloudflared` 服务。也可以不改本机证书，直接在 Cloudflare Zero Trust 控制台把该隧道的源站改为 `http://localhost:18920`，或在源站设置中开启 `No TLS Verify`。

主机端每 60 秒自动探测一次公网地址，502 恢复后会自动清除告警。建议在主机端设置中开启 **「自动启动同步」**（默认已开启）和 **「开机自动运行」**，保证登录 Windows 后源站与隧道始终在线。

## 性能与可靠性优化

- **增量文件夹刷新**：每个映射目录独立增量扫描；未变化文件按 `(大小, 毫秒级修改时间)` 复用已持久化的 SHA-256，不再重复读取文件内容，也不会为一次目录变更重建整张索引。
- **更低延迟的实时监听**：使用 MyGo `HintsOnly` 目录提示（无逐文件句柄/快照，适合大目录），80~400ms 去抖后再合并 180ms 扫描窗口；新增/移除/修改同步目录时自动重建监听器，监听失败自动回退轮询并定期重连。
- **克制内存**：上传与下载全程流式传输（不再把整个文件读入内存）；状态索引写入 500ms 去抖合并；日志缓冲区原地裁剪；删除墓碑保留 30 天且最多 10000 条；UI 每帧的统计读取为 O(1)，文件列表与筛选/排序结果按索引版本缓存。
- **全面的错误处理**：断开的盘符、被占用的文件、不可读子目录或已迁移/重命名的同步目录不会被误判为删除（不生成墓碑、不清空索引、也不会自动重建空目录）；传输进行中的文件在整个传输期间受保护，不会被轮询扫描误删；损坏的 `config.json` / `state.json` 自动备份后恢复默认；上传/下载校验 SHA-256，失败会标记状态并在下次扫描重试；SSE 空闲 60 秒自动重连，事件缓冲区满时自动触发全量对账；冲突副本保留失败会记录日志；重复错误按时间窗口限流。
- **避免覆盖较新的本地修改**：SSE 收到过期的 upsert/delete 事件时先比较本地修改时间/墓碑时间，交由常规双向对账决定方向，而不是直接覆盖；已停用的文件夹映射不会再被远端写入。
- **一致的文件列表缓存**：文件条目与其版本号在同一把锁内返回，避免 UI 把旧列表固定在一个新版本号下而长时间不刷新。
- **Windows 路径安全**：拒绝 `..` 路径穿越；符号链接/Junction 作为同步根目录时可正确遍历（不会误判为空目录），嵌套链接不会被跟随；清理空目录时严格校验根目录边界。
- **索引存储选型**：状态索引继续使用「去抖 + 原子重写」的紧凑 JSON，而不是 SQLite DLL。扫描/对账必须在内存中持有完整清单，SQLite 不会降低内存占用，却会引入 DLL 依赖、破坏 `CGO_ENABLED=0` 单文件便携构建；实测 2 万个文件时状态仅 3.9MB，保存 19ms、加载 25ms，远低于去抖窗口。若未来索引规模达到十万级以上，再考虑增量日志或嵌入式存储。

## v1.3.1 修复「大文件卡住、无速度」

现场日志：

```text
[WARN] 上传文件 Chat/C2/output/…/…CCD DryEnd.pdf 失败: 上传请求失败:
Put "https://sync.example.com/api/file?…": http2: timeout awaiting response headers
```

- **根因**：传输用的 `http.Transport` 设了固定 45 秒的 `ResponseHeaderTimeout`，而后端的响应头要等**整个请求体**被 Cloudflare 与主机端接收后才返回。工作电脑上行慢时，大文件还在传，客户端就已经按 45 秒判超时；界面同时表现为「卡住、无速度」。
- **修复**：移除固定的响应头超时，改由每个请求自己的期限控制；传输期限从「按 200 KiB/s 估算、封顶 60 分钟」改为「按 100 KiB/s 估算、封顶 24 小时」，几百 MB 的慢速上传不会被误杀。
- **新增停滞看门狗**：每 500ms 检查最后一次收到/发出字节的时间，连续 3 分钟没有任何进展才放弃并标记「传输停滞」，避免死连接一直挂着，也不会误伤仍在缓慢推进的大文件。
- **≥1MB 的文件一律走分块上传**：每块 4MB（遇到边缘 413/524 自动减半到 512KB），每块都远低于 Cloudflare 的 100MB 上限与约 100 秒的边缘超时；分块内的进度也计入实时速率，「无速度」不再出现。
- 新增实测：
  - 8 Mbit/s 限速 TCP 链路上上传 32MB：32.5 秒、1.0 MB/s、逐字节一致（`TestLargeUploadOverShapedLink`）；
  - 中途冻结的隧道会在 20 秒内被放弃且不留下半截文件（`TestFrozenTransferIsAbandoned`）；
  - 响应头被延迟到请求体接收完之后才返回时仍能成功（`TestSlowUploadSurvivesResponseHeaderDelay`，去掉修复会立即失败）。

### 真机公网实测结果（Cloudflare 隧道）

主机端运行 v1.3.2，客户端从同一台机器经 `https://sync.example.com` 上传（真实经过 Cloudflare 边缘与系统 cloudflared）：

| 文件 | 结果 | 校验 |
| :--- | :--- | :--- |
| 16 MB | 56.6 秒，0.28 MB/s | 主机端 SHA-256 一致 |
| **110 MB（超过 100 MB 单请求上限）** | **3 分 4 秒，0.60 MB/s** | 主机端 SHA-256 一致 |

100 MB 以上的文件在旧版本必然 413/524；本次 110 MB 分块上传完整到达主机，日志中只有一行「接收文件: … (110.0 MB)」，没有 `.part` 临时文件被索引或广播。

### 临时文件目录修正

真机日志暴露出分块暂存目录曾被拼成 `..synct-uploads-…`（两个点），而忽略规则匹配的是 `.synct*`，于是扫描器把正在写入的 `.part` 当成普通文件索引并向对端广播。现已改为 `.synct-uploads-…`，并在测试中直接断言该目录名被忽略规则覆盖。

## 其他本版改动

- **应用名只有一个：SyncT**。窗口标题、顶栏、托盘提示、EXE 文件属性（公司/描述）都只保留 `SyncT`。
- **所有文字可选中复制**：整个窗口是可选中的容器，日志、路径、速率、错误信息都能用鼠标拖选、双击选词、Ctrl+A 全选、Ctrl+C 复制，右键菜单含「复制/全选」。
- **日志文件**：`SyncT.log` 写在程序同级目录（便携），内容与界面日志一致；到达 2MB 即重新开始并写入一行标记，不会无限增长；设置页会显示日志位置。
- **自定义密码 → 密钥**：设置页新增「同步密码」，输入同一个密码点击「应用密码」，两端用 PBKDF2-SHA256（12 万轮，固定应用盐）派生出相同的访问密钥；密码本身不保存、不传输。直接粘贴 `st_…` 密钥或 `synct://` 连接码仍然有效。
- **默认同步目录**：两端默认使用 `<SyncT>/SyncFolder`（可通过环境变量 `SYNCT_DEFAULT_SYNC_DIR` 指定统一路径，不可用时自动回退到程序目录下的 `SyncFolder`）。

## v1.3.0 根据工作电脑真实日志的修复

工作电脑日志（`Chat/C2/log.txt`，5 分钟、289 条同步记录、101 条告警）暴露了 6 个真实问题，本版逐一修复：

1. **大文件永远传不上去（413 / 524）**：89–137 MB 的 zip 每次都失败。Cloudflare 隧道对单个请求体有 100 MB 上限，且请求超过约 100 秒会返回 524，单个 PUT 无论如何都过不去。现在超过 8 MB 的文件改为**分块上传**（`/api/upload/begin|chunk|commit|abort`），每块都在边缘限制内完成；遇到更低的边缘上限（如 413）会自动把块减半重试，断线后从服务端已收到的偏移**续传**而不是从头再来。对端若是旧版本，界面会明确提示「请把两端都升级到 v1.3.0」。
2. **一次停止产生 101 条失败告警**：停止同步或切换配置时，所有在途下载都记成 `WARN … context canceled`。现在取消被识别为正常停止，状态回到「待同步」，不写告警。
3. **成功日志淹没错误**：289 条「已下载/已上传同步」让 101 条真实告警难以发现。现在批量传输按方向聚合成一行（数量、总大小、用时、平均速率、最近文件），单个文件仍单独一行。
4. **错误信息里塞进整页 HTML**：413/524 的响应体是 Cloudflare 错误页（含 beacon 脚本），会整段写进日志和界面。现在剥离标签与脚本，只留一行摘要，并把 413/524 翻译成可操作的说明。
5. **同一文件反复产生冲突副本**：日志里有 3 个连续「哈希校验失败」，随后出现多个同名 `.conflict-` 文件。现在下载遇到摘要不符会**先重试一次**；只有本地内容确实是尚未同步的新改动时才备份冲突副本，重试不再重复生成。
6. **备份恢复的文件被静默删除**：日志显示移除的 zip 在下一次推送时又出现并再次失败。文件从备份/压缩包恢复时会保留旧的修改时间，旧的判断只看 mtime，对端较新的删除记录会把它当作过期内容删掉。现在索引记录 `SeenAt`（本端首次看到该内容的时间），参与发明判定；同时 `state.json` 持久化「待上传」标记，重启后仍知道哪些本地内容对端没有。

## v1.4.0 安全加固与同步正确性修复

本版针对审计发现的高危问题做了系统性修复，默认行为有可见变化：

### 安全

- **本地 TLS 证书改为名称约束 CA + 非 CA 叶子证书**：CA 证书带 `MaxPathLen=0`、`NameConstraints`（仅 `localhost`、`127.0.0.1/32`、`::1/128`），**CA 私钥只在签名时存在于内存，绝不落盘**；磁盘上只保留叶子证书私钥。旧版「CA-as-leaf 万能证书」在启动时会被自动识别并重新生成。
- **修复「信任本地证书」的提权命令注入**：不再通过 `cmd.exe /c` 拼接 `certutil` 与 `net stop/start`，改为经 `ShellExecuteW`（`runas`）直接调用 `certutil.exe`，参数中的路径做绝对路径 + 危险字符白名单校验，且安装前再次校验证书确为受约束的 localhost CA、磁盘私钥不与 CA 匹配。
- **禁止对端劫持本地目录映射**：`/api/manifest` 携带的 `folders[].remote_path` 默认不再能指向同步根目录之外，也绝不覆写已存在的本地目录映射。确需跨根目录映射时必须在本机显式开启 `AllowPeerRemotePath`；相对路径、`..` 段、盘符根目录一律拒绝。
- **鉴权收紧**：服务端 `AuthToken` 为空时直接拒绝所有请求（不再裸奔放行）；只接受 `X-SyncT-Token` 请求头，`?token=` 查询参数已移除；增加按客户端 IP 的失败速率限制（默认 10 次/分钟，超限返回 `429` 并带 `Retry-After`），经 Cloudflare 隧道时按 `CF-Connecting-IP` 区分真实客户端。
- **符号链接逃逸防护**：解析同步目标路径时同时做词法包含校验与 `EvalSymlinks` 实际路径校验，同步目录内植入的符号链接无法把读写重定向到目录外。
- **服务端强制同步方向**：`SyncPushOnly` 的主机拒绝 `PUT`/`POST`/`DELETE /api/file`、`/api/dirs` 与全部分块上传端点（`403`），也拒绝接收对端目录与目录删除事件；`SyncPullOnly` 的主机拒绝文件下载。

### 同步正确性

- **三方基线冲突检测**：索引持久化每个文件「上次与对端确认一致」的哈希 `synced_hashes`，对账与推送都以它而非对端当前哈希作为 `base_hash`。两台电脑离线各改同一文件时，服务端能真正识别分叉并保留 `.conflict-` 副本，不再被时钟差静默覆盖。
- **空文件夹墓碑**：目录也参与删除同步（清单新增 `dir_tombstones`，SSE 新增 `dir_delete` 事件）。删除空文件夹会传播到对端，不再「删了又活」；同步删除时只删空目录，绝不 `RemoveAll` 对端新增了文件的目录；目录重新创建后可正常复活。
- **大文件断点续传下载**：`GET /api/file` 支持 `Range`（`206`/`416`，`Accept-Ranges: bytes`），客户端对 ≥1 MB 文件按 4 MB 分段写入固定的 `.synct.part` 文件，中断后从已落盘偏移继续；下载前后校验 `X-SyncT-SHA256` 与 `X-SyncT-Size`，远端文件中途变更会自动放弃重来。
- **分块上传原子化**：分块写入不再使用 `O_APPEND` 直接追加到 `.part`，改为按服务端记录偏移 `Truncate+Seek` 写入，任何写错/超长/断流都会回滚到上一偏移；`commit` 用 `committing` 标记原子占位，重复 commit 返回 `409`，并用整文件 SHA-256 校验后才原子替换正式文件。
- **`WriteTimeout` 拆解**：服务端不再设置一刀切的 10 分钟写超时，改为在 `http.ResponseController` 上按处理器设定写期限（SSE 每帧 30 秒、普通接口 2 分钟、下载按字节进度每秒续期），大文件下载与长连 SSE 不再被服务端硬杀。

### 工程与隐私

- 默认公网域名/本地磁盘路径等个人化配置全部移除，改为 `SYNCT_PUBLIC_URL`、`SYNCT_DEFAULT_SYNC_DIR` 环境变量或设置页填写。
- `TestPackagePortableReleaseZIPs` 只在 `SYNCT_BUILD_RELEASE=1` 时执行，不再删除仓库 `bin/`，也不再覆写仓库内 `./data/config.json`；`build-portable.bat` 已同步设置该变量。

## 实测吞吐（v1.2.1）

以下为本机实测（Windows 11，回环 HTTPS，`CGO_ENABLED=0`，测试代码见 `internal/syncer/bench_transfer_test.go` 与 `latency_bench_test.go`，设置 `SYNCT_BENCH=1` 后可复现）：

| 场景 | 结果 |
| :--- | :--- |
| 4000 个 4KB 小文件，下载 | 4.2k 文件/s（8–16 并发）；64 并发约 4.0k 文件/s |
| 4000 个 4KB 小文件，上传 | 4.0k 文件/s（8–16 并发）；64 并发约 4.1k 文件/s |
| 单个 256MB 文件，下载 | 约 360–570 MB/s（含落盘、SHA-256 校验与原子重命名） |
| 首次扫描 4000 个 4KB 文件 | 约 0.45–0.64s（并行哈希；优化前约 2.4–2.9s） |
| 无变更对账 | 约 24ms |
| 40ms 模拟网络延迟，1000 个 4KB 文件 | 8 并发 187 文件/s；32 并发 710 文件/s；64 并发 1333 文件/s（无引擎开销的原始请求上限 1522 文件/s） |
| 24MB 文件经「3MB 请求上限」模拟边缘 | 自动降到 2MB 分块，62 MB/s，字节一致（`TestLargeUploadThroughEdgeCap`） |

说明：本机回环没有公网 RTT/带宽限制；40ms 代理用于观察「每个小文件一次请求」的延迟成本，与 Cloudflare 链路上的量级接近，但不等于真实公网带宽。大文件吞吐受本机磁盘、杀毒软件与测试并行读写的显著影响，实际数值会随机器变化。

## 编译与打包命令

一键生成图标资源、编译 `SyncT.exe` 并打包全部 Release ZIP：

```bash
cmd /c build-portable.bat
```

或使用 Go 命令执行完整测试与打包：

```bash
CGO_ENABLED=0 go test -count=1 -v ./...
```

补充测试命令（数据竞争检测与性能基准）：

```bash
CGO_ENABLED=1 go test -race -count=1 ./...
go test ./internal/syncer -run '^$' -bench . -benchmem
```
